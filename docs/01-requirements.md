# 用户、目标、范围和成功标准

## 用户与目标

用户是内容团队。项目读取待处理素材，检查资料和审核规则，再结合已有占用形成可确认、可查询的排期草稿。
原始时间、模型建议、用户确认和保存结果分别记录，不能把执行结束写成发布成功。

输入包括请求ID、素材ID、渠道、账号、要求时间，以及本地素材资料、审核规则和已有排期。
每个请求处理一项素材，输出审核状态、缺失或风险原因、建议时间、待确认项和实际草稿记录。

## 范围

使用Python、LangGraph、DeepSeek、SQLite和单机CLI。仅保存草稿，不接真实发布。
不开发前端、多Agent、在线服务或生产级调度平台。素材和规则是合成资料，不包含视频画面理解。

时间使用Asia/Shanghai，必须包含日期且为整点。无时区输入按上海时间解释，有偏移量的输入转换后校验。
排期只查询指定日期内、从原要求时间开始的后续整点，不支持时间窗口或跨日搜索。
冲突按渠道、账号和整点隔离；已保存草稿占位，待确认方案不占位。

## 业务规则

- 缺少标题或使用权信息不能保存；没有使用权、命中禁止标签属于硬阻断。
- 新排期选择查询返回的最早可用候选，不能跳过更早的空位。改变原要求时间时，只保存待确认方案。
- 确认绑定方案ID和版本。已确认时间仍可用时优先保存该时间，即使更早时间重新空出，也不能自动改排。
- 已确认时间被占用时重新查询、生成新版本并再次确认。确认权限只来自用户CLI输入。
- 保存前在同一业务事务内复审资料、比对查询快照和最新候选、检查确认，再写入草稿与占位。
  占用变化时要求重查；成功写入后的重复执行复用原草稿。
- `finish(blocked/missing)`必须有匹配的当前有效审核；`finish(no_slots)`还需要审核通过、有效查询，
  且查询与最新占用一致、确实没有候选。证据不足或结束原因不符时返回错误，供模型纠正。
- `finish(incomplete)`允许模型主动承认未完成，不要求此前已完成审核，也不表示业务阻断或保存成功。
- 上下文投影、摘要和历史案例不能代替完整的当前工具证据；展示与工具保护使用同一套有效性判断。
- Trace写入失败不能回滚已保存草稿或改写其状态。允许审计和记忆降级，必须明确告警，不保证审计完整。

## 成功标准

| 场景 | 验收要求 |
| --- | --- |
| 正常 | 按要求保存草稿，返回的ID可查询，数据库确有记录 |
| 资料不足 | 列出缺失项，不虚构、不保存 |
| 规则风险 | 返回规则ID和原因，模型不能豁免 |
| 时段冲突 | 18点占用、19点空闲时建议19点并等待确认，保留18点原要求 |
| 占用变化 | 新增19点占用后重新查询，建议随最新结果调整 |
| 错选候选 | 模型选择20点但17点可用时，程序拒绝，允许根据工具观察纠正 |
| 确认后变化 | 重新检查审核与占用；有效确认不可擅自换时，过期确认不能放行 |
| 重复与并发 | 同ID同内容只产生一份草稿；同ID不同内容拒绝；竞争不能绕过唯一占位 |
| 保存失败 | 事务回滚，不留半份草稿或占位，不返回虚假成功 |
| 重启恢复 | 重建应用后可继续；写入先于检查点时不重复保存，累计预算不清零 |
| 结束与超限 | 结束原因有当前证据；业务拒绝、执行故障和预算耗尽分别记录 |
| 日志故障 | 业务结果仍以数据库为准，警告写标准错误，`--json`标准输出仍可解析 |
| 记忆和日志同时故障 | 当前业务仍可降级处理，故障日志不会递归重试 |

输入、实际输出、Trace和测试结果见[评估文档](03-evaluation.md)。
